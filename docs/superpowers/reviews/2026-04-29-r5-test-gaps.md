`cargo clippy --workspace --all-targets -- -D warnings` clean,
both confirmed before each `git commit`.  Standing rules
(no `--no-verify`, no `panic!`/`unwrap`/`expect` in production

## Tests added (by area)

### Bound-via-If / known-bits edge cases (commit `d2e88d9`)

`crates/opt/src/indirect_branch_resolve/jump_table_tests.rs` — 5 tests:

* **`bound_via_predecessor_if_join_with_multi_input_phi_is_unbounded`** —
  pins the documented limitation that the `same_value` walk only
  collapses single-input (trivial) phis.  When two control
  predecessors of the dispatch region each prove `idx < N`, the
  dispatch's read of idx is a 3-input ControlPhi (token + 2 values)
  which `same_value` doesn't collapse, so the per-path `idx_var`
  doesn't unify with `idx_in_dispatch` and each path's bound resolves
  to None.  Combined join bound is therefore None.
* **`bound_via_predecessor_if_join_fails_closed_when_one_path_unbounded`** —
  pins the fail-closed semantics: if one predecessor reaches Entry
  without an If on the path, the join's bound is None even if the
  other predecessor proves a bound.
* **`bound_via_known_bits_returns_none_for_unreachable_output`** —
  pins the reachability-scope contract: an output detached from the
  entry preorder gets `Kb::default()` (all-unknown) and yields None.
  R3-extension introduced this scoping via the worklist seed; this
  test pins the contract callers depend on.
* **`bound_from_if_condition_idx_equal_n_true_returns_none`** — pins
  the H2 soundness fix: `idx == N` taken-true must NOT yield a
  `0..N` enumeration bound (idx is the single value `{N}`, not a
  range).
* **`bound_from_if_condition_with_n_on_lhs_does_not_match`** — pins
  the operand-order limitation: `IntCmp(N, idx)` is non-commutative
  so `int_cmp_any` doesn't bind `idx_var` to the swapped side.
  Documented limitation; future tightening would surface here.

### Sless-as-Less current behaviour (commit `270f32f`)

`crates/opt/src/indirect_branch_resolve/jump_table_tests.rs` — 1 test:

* **`bound_from_if_condition_signed_less_treated_as_unsigned_bound`** —
  pins the current behaviour and flags the soundness caveat: signed
  `idx < N` true yields bound `N`, the same as unsigned.  This is
  sound *only when* the dispatch path also proves `idx >= 0`
  (typical when the prior signed-zero check has been folded into a
  combined arm).  Without that precondition the bound is unsound.

### Orchestrator: split invalidation + tail-call boundaries (commit `a6ee354`)

`crates/strider/src/indirect_resolve_tier2/orchestrator.rs` — 7 tests:

* **`apply_split_invalidation_evicts_on_shrunk_count`** — the
  positive eviction trigger that `apply_split_invalidation_noop_on_empty_snapshot`
  did not exercise.  When the prev_snapshot says N insns and
  new_cfg has fewer, the cache entry is removed.
* **`apply_split_invalidation_preserves_on_unchanged_count`** —
  negative case: same insn count → entry stays.  Pre-fix an
  off-by-one at the `<` boundary (e.g. accidental `<=`) would
  over-evict every region every iteration.
* **`is_tail_call_target_below_start_addr_is_tail_call`** — pins
  the `<` boundary: target == start_addr is NOT tail; one below IS.
* **`is_tail_call_allow_code_before_start_addr_disables_below_check`** —
  pins the `allow_code_before_start_addr` interaction.
* **`is_tail_call_above_fn_max_size_is_tail_call`** — pins the
  `<=` end_exclusive boundary (target == start_addr + fn_max_size
  is tail).
* **`is_tail_call_no_fn_max_size_means_above_is_intra_fn`** —
  documents that without `fn_max_size`, only the below-start branch
  triggers.
* **`is_tail_call_fn_max_size_saturates_on_overflow`** — pins
  `saturating_add` against u64 overflow.

### Orchestrator: read_or_init_var dedup (commit `f631639`)

`crates/strider/src/indirect_resolve_tier2/orchestrator.rs` — 4 tests:

* **`read_or_init_var_returns_cached_exit_value_when_present`** —

* **`read_or_init_var_scan_returns_existing_initial_var_no_dup`** —

## Bugs surfaced + deferred

### Sless-as-Less unsound when dispatch path doesn't prove idx >= 0

* **File:line**: `crates/opt/src/indirect_branch_resolve/jump_table.rs:501`
* **Confidence**: medium-high (the unsoundness is real; whether it
  manifests in practice depends on compiler emission patterns we
  haven't verified against a real-arch corpus).
* **Root cause**: `bound_from_if_condition` treats `IntCmpOp::Sless`
  identically to `IntCmpOp::Less` and returns `Some(N)` on the true
  branch.  For signed types where `idx` could be negative, the
  bound is wrong — runtime idx ∈ [INT_MIN, N-1], which as unsigned
  is `[0, N-1] ∪ [2^bits − |INT_MIN|, 2^bits − 1]`.
* **Why not fixed in R5**: the soundness caveat applies only when
  the dispatch path *also* lacks a dominating `Sless 0` test that
  proves idx >= 0.  Real compilers typically emit the pair (or fold
  it to an unsigned `Less` test, since `(uint)idx < N` covers both
  the >= 0 and < N halves in one compare).  Determining whether
  any real binary in the project's fixture corpus reaches the
  dispatch with negative idx requires lifting & inspecting the
  compiler emission patterns, which is out of scope for R5.
* **Proposed remediation**: tighten `bound_from_if_condition` to
  require either (a) the dominating control path also proves
  `idx >= 0` via an `Sless 0` / `SlessEqual -1` test on the false
  branch, or (b) restrict to cmp ops where signed and unsigned
  agree at the relevant width (rare).  Path (a) is the natural
  follow-up; the test
  `bound_from_if_condition_signed_less_treated_as_unsigned_bound`
  pins the current behaviour so any tightening surfaces explicitly.

### F-R1-A bit-width gap: ShiftLeft on narrow types (R1 deferral)

* **File:line**: `crates/opt/src/indirect_branch_resolve/stack_array.rs:433`
* **Confidence**: low (cannot construct a real-arch fixture).
* **Root cause**: `extract_idx_and_stride` rejects `s_u128 >= 64`
  but doesn't check the shift node's *output bit width*.  A
  `ShiftLeft(idx_u8, 8)` evaluates to 0 in Sleigh's runtime
  semantics (R1 fix in `eval_int.rs`) but the helper computes
  stride = 1 << 8 = 256 and uses it.
* **Why not fixed**: a real lifter never emits `<< 8` on a U8
  varnode because addressing is wider than 8 bits — the stride
  must be expressed at the address-arithmetic width (U32 / U64).
  The path is dead in practice; fixing it without a reproducer
  risks introducing a new bug.  R1 documented this conclusion;
  R5 confirms it remains the right call.
* **Proposed remediation**: track per-node output type at the
  shift, reject `s >= bit_width(idx_ty)`.  Defer until a real
  fixture demonstrates the divergence.

## Open follow-ups

* **Multi-input phi unification in `same_value`** — the new
  `bound_via_predecessor_if_join_with_multi_input_phi_is_unbounded`
  test pins the limitation; tightening it would let the
  predecessor-If walk prove a max-bound across diamond joins.
  Worth trying if the indirect-branch resolver hits real-binary
  patterns with such shapes.
* **`flatten_add_tree` budget cap** — the `*budget >= 32` cap is
  not exercised by any test (the function is private and not
  `pub(crate)`).  Adding `pub(crate)` and a cap-hit test would
  pin the soundness ceiling.  Low priority.
* **Validator Layer A reachability scope** — Layer A correctly
  skips zombie nodes via the `walk_graph` boundary, but no test
  exercises a deliberately-malformed reachable node alongside a
  zombie to confirm the boundary holds in both directions.  Nice-
  to-have.
* **`apply_link_register` / `apply_tail_call` arity tests for
  callee_saved overlapping caller_saved** — ARM's `lr` is both
  callee_saved and the link register; the existing tests cover
  the canonical cases but not this overlap explicitly.  The
  current implementations don't special-case overlap, which is
  the right behaviour, but a test could pin it.
* **`flatten_add_tree` constant-folding interaction** — could
  benefit from a dedicated test that exercises a 32+ deep Add
  tree (the budget-cap path).

## Five-round retrospective

The five rounds in aggregate transformed the indirect-branch-
resolution stack and its dependencies from "works on the fixture
corpus" to "documented invariants pinned by tests, with the
critical correctness bugs paid down".  In the order they happened:

* **R1** found and fixed two genuine shift-semantics bugs in
  `opt::constant_fold` and `opt::known_bits` that previously
  diverged from Sleigh's runtime semantics on `r >= bits` — every
  one of the project's 15 architectures was affected, but the
  divergence rarely manifests because real lifters don't emit
  shift-by-bits-or-more.  Still: a foundation crack worth fixing.
* **R2** dogfooded the in-house `pattern` crate inside
  `stack_array::strip_target_mask`, replacing arm-by-arm dispatch
  with auto-commutative `pattern::and` / `pattern::or` builders.
  Net: less code, better-tested, and a real exercise of the
  pattern API's commutativity / capture facilities.
* **R3** (and R3-extension) extracted the `analyze_known_bits`
  helper as a reusable analyzer (the jump-table classifier was the
  first non-pass caller), deleted `compute_max_mask`, and added the
  `Graph::kind_of_output` accessor that R4 then propagated to ~50
  callsites.
* **R4** focused on readability: stripping stale `F5/W-numbered`
  project codenames from comments, renaming
  `manual_rewrite.rs` → `graph_rewriter.rs` to match the actual
  type, merging tiny `insn::{memory,misc}` submodules.  Pure
  hygiene; no behaviour change but a substantial signal-to-noise
  improvement for future reviewers.
* **R5** (this round) audited test coverage on the surface area
  R1–R4 touched and on a few historically-thin spots
  (`is_tail_call`, `read_or_init_var`, `apply_split_invalidation`,
  the predecessor-If join, the reachability-scope contract).
  Found no new bugs but pinned 17 contracts that previously
  existed only as doc-comments or implicit testing.

**Hand-off to the next deep-CR cycle**:

* The bound-via-If walk is the highest-value place to keep looking
  for real bugs.  Two limitations are documented (multi-input phi
  no-unify; Sless-as-Less); a third may exist around control-flow
  shapes that involve a `Call` between the dominating `If` and the
  dispatch (the current walk transparently passes through Call's
  control output, which is fine for tail-call semantics but could
  be a divergence point for non-tail intra-fn calls).
* The pattern crate's commutativity is now well-tested, but
  composability of `WithCapture { inner, var }` with deep nesting
  hasn't been stress-tested.  If a future feature adds a
  multi-stage capture pattern, exercise the bindings-rollback path.
* The orchestrator's `is_tail_call` and `apply_split_invalidation`
  are now well-covered.  The next likely bug-magnet area is the
  fixed-point convergence cap (`IndirectResolutionDidNotConverge`)
  — currently no test deliberately constructs an oscillating CFG.
* Whoever runs R6: the SIMPLIFICATION_REVIEW.md file at the repo
  root (untracked) is leftover scratch from R3-simplification and
