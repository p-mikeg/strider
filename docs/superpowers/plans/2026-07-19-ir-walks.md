# Python Stable API — Plan 2: IR Walks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the IR graph walks to Python (`Function.cfg_walk` / `data_walk` / `walk(node)` / `mem_walk`) and add the missing runtime symmetry `Node.outputs()`.

**Architecture:** All four walks are pure structural traversals native to `strider-ir` — `cfg_reachable` (control) and `walk_graph` (data+control) already exist; `walk(node)` needs a public seeded entry (`IRWalker::walk_from`); `mem_walk` is a new forward memory-token traversal built on the existing `memory_output_of` + `value_uses` accessors. No `strider-opt` dependency. The Python layer adds thin `#[pymethods]` on `strider.ir.Function` / `strider.ir.Node` returning `list[Node]`, following the existing `inputs()` handle pattern.

**Tech Stack:** Rust + PyO3 0.22 (`strider-py`, `strider-ir`), maturin, pytest.

## Global Constraints

- **No O() regression:** every walk is O(reachable nodes + edges); no per-node re-walk.
- **Deviation from the design spec (§F), deliberate:** `mem_walk` is a native structural memory-chain walk, NOT the alias-aware reaching-def finder in `strider-opt`'s `mem_ssa`. The `mem_ssa` extraction the spec floated is NOT needed for a structural walk and is out of scope. Rationale: `cfg_walk`/`data_walk`/`mem_walk` are one consistent family of structural reachability over the three edge kinds; the alias-aware "which store does this load read" is a heavier, separate feature.
- **`constraints.user`, generic pattern slots, and kind roots are Plan 3**, not this plan.
- **Return shape:** every walk returns `list[Node]` (Python `strider.ir.Node` handles); `Node.outputs()` returns `list[Node]`.
- **Rebuild before pytest:** `uv run maturin develop` from the **workspace root**, never `crates/strider-py`; verify the `.so` mtime.
- **Full gate before merge:** `cargo test --workspace`, `clippy --workspace`, `cargo doc -D warnings`, `cargo fmt --check`, `pytest` all green.

## Task 2: `memory_reachable` — forward memory-token traversal

**Files:**
- Modify: `crates/strider-ir/src/walk/mod.rs`
- Test: `crates/strider-ir/src/walk/mod.rs` `#[cfg(test)]`

**Interfaces:**
- Produces: `pub fn memory_reachable(function: &Function, entry: NodeId) -> Vec<NodeId>` — the memory-touching nodes (Load, Store, Call, CallOther, MemPhi) reachable by following memory-token edges forward from the function's `InitialMemory`, in BFS order. `InitialMemory` itself is included as the root.

**Design:** the memory chain is rooted at the unique `InitialMemory` node. Following its `Memory` output to its uses gives the next memory-touching nodes; each producer (`Store`/`Call`/`CallOther`/`MemPhi`) has its own `Memory` output that continues the chain; `Load` consumes a memory token but produces none, so it is a leaf. This is a forward BFS over `memory_output_of(node) -> value_uses(vid) -> consumer nodes`.

```rust
use crate::node::{NodeKind, ValueKind};
use crate::IRViewer;

/// The memory-touching nodes reachable by following memory-token edges
/// forward from the function's `InitialMemory` root, in BFS order.
///
/// The memory chain is rooted at the unique `InitialMemory`; its `Memory`
/// output feeds the next memory op (`Load` / `Store` / `Call` / `CallOther` /
/// `MemPhi`), and each producer's own `Memory` output continues the chain.
/// `Load` is a leaf (consumes a memory token, produces none). The
/// `InitialMemory` root is included.
pub fn memory_reachable(function: &Function, entry: NodeId) -> Vec<NodeId> {
    let graph = function.graph();
    // Find the InitialMemory root among control-reachable nodes.
    let reachable = cfg_reachable(graph, entry);
    let Some(root) = function
        .reachable_kind_iter(&reachable)
        .find(|(_, k)| matches!(k, NodeKind::InitialMemory))
        .map(|(n, _)| n)
    else {
        return Vec::new();
    };

    let mut seen = DenseEntitySet::<NodeId>::new();
    let mut order = Vec::new();
    let mut work = vec![root];
    seen.insert(root);
    while let Some(node) = work.pop() {
        order.push(node);
        // Follow this node's Memory output (if any) to its consumers.
        if let Ok(mem_out) = function.memory_output_of(node) {
            for use_id in graph.value_uses(mem_out) {
                let consumer = graph.use_consumer(use_id);
                if !seen.contains(consumer) {
                    seen.insert(consumer);
                    work.push(consumer);
                }
            }
        }
    }
    order
}
```

```rust
    /// Control-only reachability (the CFG skeleton) from the entry, as `Node`s.
    fn cfg_walk(slf: Py<Self>, py: Python<'_>) -> PyResult<Vec<crate::node::PyNode>> {
        let ids: Vec<u32> = slf.borrow(py).with_read_value(|function| {
            strider_ir::walk::cfg_reachable(function.graph(), function.entry())
                .iter()
                .map(|n| n.as_u32())
                .collect()
        })?;
        Self::nodes_from_ids(slf, py, ids)
    }

    /// Every node reachable from the entry (data-in + control-out), pre-order.
    fn data_walk(slf: Py<Self>, py: Python<'_>) -> PyResult<Vec<crate::node::PyNode>> {
        let ids: Vec<u32> = slf.borrow(py).with_read_value(|function| {
            function.walk().map(|n| n.as_u32()).collect()
        })?;
        Self::nodes_from_ids(slf, py, ids)
    }

    /// Every node reachable from `node_id` (data-in + control-out), pre-order.
    fn walk(slf: Py<Self>, py: Python<'_>, node_id: u32) -> PyResult<Vec<crate::node::PyNode>> {
        let ids: Vec<u32> = slf.borrow(py).with_read(|function| {
            let nid = function
                .graph()
                .node_id_from_u32(node_id)
                .ok_or_else(|| into_strider_err(anyhow::anyhow!("no node with id {node_id}")))?;
            Ok(function.walk_from(nid).map(|n| n.as_u32()).collect())
        })?;
        Self::nodes_from_ids(slf, py, ids)
    }
```

And a private (non-`#[pymethods]`) helper `impl PyFunction` block:

```rust
impl PyFunction {
    /// Build `Node` handles for `ids`, cloning the `Py<Self>` handle per node
    /// (mirrors `Node.inputs`). Ids are collected under a read borrow that has
    /// been dropped before this runs.
    fn nodes_from_ids(
        slf: Py<Self>,
        py: Python<'_>,
        ids: Vec<u32>,
    ) -> PyResult<Vec<crate::node::PyNode>> {
        let mut out = Vec::with_capacity(ids.len());
        for id in ids {
            out.push(crate::node::PyNode::new(py, slf.clone_ref(py), id)?);
        }
        Ok(out)
    }
}
```

```rust
    /// The nodes that consume this node's outputs, as a list of `Node`s — the
    /// forward counterpart to `inputs()`.
    ///
    /// Each of this node's output `ValueId`s may feed zero or more consumer
    /// nodes; every consumer is returned (a consumer appears once per edge it
    /// draws from this node). Order follows output-slot then use order.
    fn outputs(&self, py: Python<'_>) -> PyResult<Vec<PyNode>> {
        let consumer_ids: Vec<u32> = self.with_node(py, |function, nid| {
            let graph = function.graph();
            let mut ids = Vec::new();
            for &out in graph.node_outputs(nid) {
                for use_id in graph.value_uses(out) {
                    ids.push(graph.use_consumer(use_id).as_u32());
                }
            }
            ids
        })?;
        let mut out = Vec::with_capacity(consumer_ids.len());
        for cid in consumer_ids {
            out.push(PyNode::new(py, self.function.clone_ref(py), cid)?);
        }
        Ok(out)
    }
```
