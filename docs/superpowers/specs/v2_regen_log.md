# v2_baseline regeneration log

`v2_baseline.rs` was originally pinned at the egg-based v2 optimizer pipeline
(`PipelineV2`).  When the egg infrastructure was retired, the entry-point was
redirected at `common::analyze` (which now routes through the imperative
pipeline, `Strider::build_optimizer_pipeline`).  For 1517 (arch, case,
fn_name) fixtures the imperative pipeline produces structurally different IR
than the retired egg pipeline.  Their snapshots were regenerated with
`INSTA_UPDATE=always cargo test -p strider --test v2_baseline`.

Each regeneration is part of the documented "egraph-aliasing-gap" family:
the egg-based pipeline applied more aggressive canonicalisations
(e.g. eliminating `StackStore` of zero-init constants on x86) than the
imperative `ConstantFold` / `KnownBits` rules — but no callsites or
downstream consumers depend on those canonicalisations, and the
imperative shape is what the production pipeline has always emitted.

Snapshots that were *not* regenerated remained byte-identical between the
two pipelines (644 of 2161 fixtures).

## Verification

The regenerated `v2__*.snap` files match the corresponding `v3__*.snap`
files byte-for-byte modulo the `source:` header line, because both tests
now back onto the same imperative pipeline via `common::analyze`.
